# Languages (i18n)

The UI languages are English (`en`) and Russian (`ru`); Uzbek (`uz`, Latin script) is planned. Code, comments,
identifiers, commits and docs stay English; only UI strings are translated, and they only reach the screen through
`t()` (src/i18n). The simulation, replays, scores, the board and the verifier never depend on the language. The Worker
answers with CODES only (`reason: 'words'`, ...); the client maps them to the catalog.

## How it works

- `src/i18n/en.ts`: the source of truth, a typed object `key -> text` with `{name}` placeholders. `Key` is its key set.
- `src/i18n/<lang>.ts`: typed `Catalog` (= `Record<Key, string>`): a missing or extra key is a TypeScript error.
- `src/i18n/index.ts`: `t(key, params)`, `setLang`, `onLangChange`, `resolveLang`, `chooseLang`. A key missing at
  runtime falls back to English; an unknown key returns the key itself; nothing throws.
- `src/i18n/langs.ts`: `LANGS` (data), each language's OWN name (the switch always shows "EN", "RU", "ENGLISH",
  "РУССКИЙ" whatever the current language is), the `<html lang>` value.
- `src/i18n/format.ts`: ONE helper per kind: `fmtInt` (ru: `12 345`, a normal space: the font has no thin space),
  `fmtDec` (ru: decimal comma, `X2,50`), `fmtDate` (ru: `DD.MM.YYYY`), `fmtDayMonth` (the HUD's daily label) and
  `plural(n, forms)` through `Intl.PluralRules`. English keeps the previous formats exactly. Prefer wording without
  plurals ("ВОЛНА 3").
- The setting `language: 'auto' | 'en' | 'ru'` lives in the save (src/storage.ts); old saves without it load as
  `'auto'`, unknown values are ignored (`'auto'`). Only a MANUAL choice is stored; `'auto'` is never replaced by the
  detected language, so a new language (Uzbek) re-detects for everyone on `'auto'`.
- `src/i18n/detect.ts`: the detection table (data). The browser's languages are read in order of preference and the
  first one the game knows wins: `ru*` -> ru, `uz*` -> ru FOR NOW, `en*` -> en, nothing known -> en.
- The language is applied in src/main.ts before any scene starts (the first-run card is already translated). The
  title screen has a language row ("[EN]  RU"); Settings has LANGUAGE (hidden in Settings opened from the pause
  menu: no switch during a run). A switch rebuilds the current page in place (same page, same focus) and re-renders
  the HTML board panel and overlay.
- No URL parameter and no debug hook select the language; tests store it in localStorage before the page loads.

## Adding a language (e.g. Uzbek)

1. `src/i18n/langs.ts`: append the code to `LANGS`, its own names to `OWN_NAME` (`UZ` / `OʻZBEKCHA`), `HTML_LANG`.
2. `src/i18n/uz.ts`: `export const uz: Catalog = { ... }` (the type lists every key). Register it in `CATALOG`
   (src/i18n/index.ts).
3. `src/i18n/detect.ts`: change the `uz` row to `lang: 'uz'`.
4. Font: `npm test` (tests/i18n.test.ts) fails for every character the bitmap font lacks (it would render as "?").
5. Fit (below), `npm run e2e:layout` and the phone checks with the new language added to their language loops,
   screenshots, and a native speaker's review of the glossary.
6. Formats: add the language to `src/i18n/format.ts` if it differs from English.

### Uzbek notes

- Latin script (the official one): A-Z plus the digraphs Sh, Ch, Ng and the letters Oʻ / Gʻ, written with U+02BB
  (MODIFIER LETTER TURNED COMMA); the tutuq belgisi (glottal stop) is U+02BC. In practice people type U+2018 /
  U+2019 or a plain apostrophe U+0027.
- The bitmap font (public/fonts/px8.xml, made by tools/gen_font.py) HAS U+0027 and U+2018-U+201E, but NOT U+02BB or
  U+02BC: their range (0x2B0-0x2FF) is not in `RANGES`. Either add `(0x2BB, 0x2BC)` to `RANGES` in tools/gen_font.py
  (only if Press Start 2P draws them; the generator skips empty glyphs) or draw the two 8x8 glyphs by hand (a turned
  comma above the baseline). Until then the catalog must use U+2018 (`Oʻ` -> `O‘`).
- Casing: Uzbek uses plain Latin upper / lower case (no dotted / dotless i). The UI is uppercase: `OʻYINNI BOSHLASH`.
- Plurals: Uzbek nouns take `-lar`, but after a number the noun stays singular ("3 toʻlqin"): no plural forms needed.
- Many Uzbek players read Russian: detection sends `uz*` to Russian until Uzbek ships.

## Fit rules

- The portrait game is about 250-290 game px wide with an 8 px font (about 30 characters per line); Russian runs
  25-40% longer than English. Fit by shorter synonyms, the menu's own fallback (16 px rows drop to 8 px and wrap at
  word boundaries) and wrapping; never below 8 px, never a word broken in the middle, no abbreviations a reader would
  not understand ("НАСТР." is not allowed).
- Fixed columns: hero names <= 6 letters (best scores and the board table), dates 10 characters (`08.11.2026`),
  scores <= 7 characters with grouping (`999 999`).
- Tight places: the death panel (about 28 characters per line), the hero stat lines (<= 18), the HUD (the wave and
  the daily label share their row with other readouts), the submit panel buttons, the board panel (HTML, wraps).
- Checks: tests/i18n.test.ts (keys, placeholders, font coverage, no hard-coded text, no unused key), the language
  loops in tests-e2e/layout.cjs (every menu page, the run HUD and the portrait shell in both languages) and
  tests-e2e/i18n.cjs (switching, leaks, Cyrillic input, screenshots).

## Not translated yet

- The static pages (privacy.html, rules.html, credits.html, license.html) and the desktop page footer stay English:
  they are legal text; translating them is the next step.
- The game's name (TITLE) is a brand and is not translated.
